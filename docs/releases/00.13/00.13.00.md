# Release Notes - Versão 0.13.0

**Data de Lançamento:** 19 de Outubro de 2026

## 📝 Resumo Executivo

A versão 0.13.0 traz uma experiência de inicialização e execução totalmente automatizada e simplificada em um único comando ("Zero-Click"). Agora, o sistema pode ser executado instantaneamente em qualquer computador ou servidor com isolamento completo, sem a necessidade de instalar manualmente ferramentas de desenvolvimento ou realizar configurações manuais de banco de dados e filas.

Toda a preparação inicial do banco de dados e os serviços de apoio são configurados e validados automaticamente nos bastidores antes que a aplicação receba qualquer operação financeira. Além disso, os operadores e equipes de suporte passam a contar com validações automatizadas de integridade e estabilidade que podem ser disparadas de forma isolada, garantindo total segurança, preservação contínua de saldos e prontidão para processamento financeiro contínuo.

---

## 🆕 Recursos Adicionados

- **Execução Automatizada "Zero-Click" via Docker Compose:**
  - Inicialização completa com um único comando (`docker compose up -d --build` ou `bun run docker:up`), orquestrando banco de dados, filas e aplicação com ordenação de dependências inteligente.
  - Serviço de migrações automáticas (`migration`) acionado no boot logo após a prontidão do PostgreSQL, garantindo que todas as tabelas, triggers e restrições financeiras estejam ativas antes do tráfego.
  - Orquestração com bloqueio condicional (`service_completed_successfully`), impedindo que a aplicação receba requisições antes da criação das tabelas contábeis.
  - Volume persistente nomeado (`postgres_data`) configurado no PostgreSQL, mantendo saldos, carteiras e extratos salvos entre reinicializações de containers.
- **Ambiente de Testes e Validação em Container Isolado:**
  - Perfil dedicado de testes (`profiles: ["test"]`) no `docker-compose.yml`, permitindo rodar a suíte completa de validação (`bun run docker:test`) ou testes de carga (`bun run docker:load`) em container Linux isolado sem requerer Bun instalado na máquina host.
  - Suporte completo à execução de testes de concorrência, multi-instância e failover dentro do container Docker com isolamento de rede.
- **Otimização de Contexto de Construção com `.dockerignore`:**
  - Inclusão do arquivo `.dockerignore` isolando `node_modules` locais (macOS Darwin), logs e histórico git, acelerando drasticamente o build e evitando incompatibilidade binária entre arquiteturas.
- **Atalhos Operacionais Unificados no `package.json`:**
  - Novos comandos para simplificar a operação: `docker:infra`, `docker:up`, `docker:down`, `docker:test`, `docker:check`, `docker:load` e `docker:build`.

## 🔧 Modificações

- **Simplificação e Otimização de Instâncias:** Configuração padrão do serviço `app` unificada em 1 réplica principal mapeando a porta `3000:3000`.
- **Healthcheck Nativo no Container:** Implementado probe nativo via `bun` avaliando `/health/ready` periodicamente a cada 5s sem dependência de ferramentas externas como curl.
- **Documentação de Modos de Execução no `README.md`:** Seção "Como Rodar o Projeto" totalmente reformulada com divisão clara entre Opção A (Tudo via Docker) e Opção B (Desenvolvimento nativo com Bun no Host), acompanhada de tabela comparativa e guia de comandos.
- **Elevação de Versão:** Atualização SemVer para `0.13.0` no `package.json`.

## 🐛 Correções

- **Prevenção de Incompatibilidade de Dependências Nativas:** A exclusão explícita de `node_modules` via `.dockerignore` corrigiu a contaminação de binários host/container no build Linux.
- **Resolução de Ausência de Tabelas em Banco Novo:** O encadeamento de migrações automáticas elimina falhas de inicialização em instâncias com banco PostgreSQL limpo.

## 🏗️ Alterações Estruturais

- Adição do arquivo `.dockerignore` na raiz do projeto.
- Atualização do `docker-compose.yml` com serviço `migration`, volume `postgres_data`, healthcheck do app e serviço `test`.
- Novos scripts de gerenciamento no `package.json`.
