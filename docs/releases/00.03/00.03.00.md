# Release Notes - Versão 0.3.0

**Data de Lançamento:** 17 de outubro de 2026

## 📝 Resumo Executivo

A versão 0.3.0 disponibiliza a API REST do processador de apostas, permitindo que provedores de jogos e sistemas de gestão criem carteiras de jogadores e realizem transações de apostas, ganhos, cancelamentos e estornos com segurança total. A nova interface impede cobranças duplicadas em conexões instáveis através de confirmação inteligente de transações já recebidas, oferece extrato detalhado para consulta de histórico e conta com auditoria contínua para certificar que o saldo dos jogadores esteja rigorosamente correto.

---

## 🆕 Recursos Adicionados

- **Endpoints de Carteiras (`/wallets`):**
  - `POST /wallets`: criação atômica de carteiras vinculadas a jogador e moeda, com lançamento contábil `OPENING` se houver saldo inicial.
  - `GET /wallets/:id`: consulta de dados cadastrais, saldo atual e versão de concorrência.
  - `GET /wallets/:id/ledger`: extrato de lançamentos com paginação determinística via cursor opaco (`base64` do `seq`).
  - `POST /wallets/:id/reconciliation`: auditoria contábil matemática que compara o saldo armazenado com o somatório de créditos e débitos do livro-razão.
- **Endpoints de Transações (`/transactions`):**
  - `POST /transactions`: processamento de apostas (`BET`, `WIN`, `LOSS`, `REFUND`, `ROLLBACK`) com header `Idempotency-Key` e lock pessimista por linha.
  - Retornos HTTP padronizados: `201 Created` para nova transação, `200 OK` para replay idempotente com flag `idempotentReplay: true`, `202 Accepted` para transações com referência pendente (`PENDING_REFERENCE`) e `422 Unprocessable Entity` para rejeições de negócio (`INSUFFICIENT_FUNDS`, `ALREADY_REVERSED`, etc.).
  - `GET /transactions/:id`: consulta de transação por identificador interno.
  - `GET /transactions/external/:providerId/:externalId`: consulta de transação por chave externa do provedor de jogos.
- **Camada de Aplicação:**
  - 6 Casos de Uso integrados ao `UnitOfWork`: `CreateWalletUseCase`, `ProcessWagerTransactionUseCase`, `GetWalletUseCase`, `GetLedgerUseCase`, `GetTransactionUseCase` e `ReconcileWalletUseCase`.
  - DTOs tipados com validação estrita via esquemas Zod (`CreateWalletSchema`, `ProcessTransactionSchema`, `GetLedgerQuerySchema`).
  - Porta de identidade e guard de autenticação no-op (`ProviderIdentityPort` e `AuthGuard`).
  - Filtro global de exceções (`HttpExceptionFilter`) padronizando o envelope `{ error: { code, message, retryable } }`.
- **Suíte de Testes:**
  - 10 novos cenários unitários para os casos de uso (`test/unit/use-cases.test.ts`).
  - 15 novos cenários de integração HTTP reais contra o PostgreSQL e NestJS (`test/integration/http-api.test.ts`).

## 🔧 Modificações

- `src/main.ts` atualizado para carregar o `HttpModule` e registrar o `HttpExceptionFilter` globalmente.
- Adicionados os códigos de falha `WALLET_ALREADY_EXISTS` e `TRANSACTION_NOT_FOUND` ao enum de domínio `FailureCode`.
- Incremento da versão do projeto para `0.3.0` no `package.json`.

---

## 🐛 Correções

- Reordenação da persistência no caso de uso de processamento de transações para inserir a `WagerTransaction` antes do `WalletLedgerEntry`, respeitando a chave estrangeira relacional no PostgreSQL.
- Tratamento explícito de tipos e asserções estritas no TypeScript em ambiente Bun com `strict` e `noUncheckedIndexedAccess`.
